# 백업과 복구

## 보관 대상

| 자료 | 보관 위치 | 복구에 필요한 것 |
|---|---|---|
| DB 구조 | 이 Git 레포 | 검증한 마이그레이션 버전·커밋, 제품별 설정 |
| PostgreSQL 운영 데이터 | Supabase 관리 백업과 권한 제한된 별도 백업 저장소 | 복구 시각, 암호화된 파일, 체크섬, 복구 담당자 |
| Storage·R2 실제 파일 | 객체 저장소의 별도 백업 또는 버전 관리 | 버킷, 키, 보존 기간, 접근 정책 |
| Auth·서비스 설정 | 비밀 관리 도구와 환경별 설정 기록 | 인증 제공자, 리디렉션, API 노출 스키마, 결제 웹훅, 키 재설정 항목 |

Git에 보관하는 것은 구조와 합성 예제입니다. 실제 고객 덤프, 인증·결제 데이터, API 키와 토큰은 Git에 올리지 않습니다. Supabase DB 백업에는 Storage API 객체의 본문이 포함되지 않으므로 파일은 별도로 보존합니다.

## 복구 연습

1. 복원 대상 제품과 DB 백업 시각, Git 커밋, 객체 백업 시각을 기록합니다.
2. 별도 복구 환경을 준비합니다. 구조만 필요하면 해당 Git 버전의 공통 및 제품 마이그레이션을 새 환경에 적용합니다. 전체 관리 백업을 복원할 때는 복원된 마이그레이션 이력부터 확인합니다.
3. 운영 데이터를 복구할 때는 대상 범위에 맞는 Supabase 복원 절차를 사용합니다. 제품 단독 이전에서는 제품 테이블과 연결된 업체·멤버십·구독·이용권·사용자 ID를 함께 매핑합니다.
4. 객체 파일, Auth 설정과 서비스 환경값을 확인합니다. 테스트 로그인, A/B/C 격리, 구매한 기능, 환불 처리, 파일 다운로드를 검증합니다.
5. 데이터 건수·복구 시각·누락 항목을 기록합니다. 전환이 필요하면 기존 환경의 복귀 경로를 유지하고, 검증을 통과한 뒤 연결을 변경합니다.
